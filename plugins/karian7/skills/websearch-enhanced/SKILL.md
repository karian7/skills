# 네이버 + 1차 소스 조사

국내 대상을 조사할 때의 경로. **네이버 뉴스 탭으로 보도를, 웹문서 탭으로 공고·기관
페이지를 훑고, 내장 웹 검색 도구로 1차 소스를 잡고, 원문을 직접 읽어 교차
확인한다.** 네이버 SERP 수집과 기사 본문
추출에는 브라우저·API 키 없이 이 스킬에 포함된 `requests` 기반 스크립트를 쓴다.

## 실행 환경별 도구 매핑

| 목적 | Claude Code | Codex |
|---|---|---|
| 웹 검색 | `WebSearch` | `web.run`의 `search_query` |
| 페이지 열기 | `WebFetch` | `web.run`의 `open` |
| 페이지 내 검색 | 페이지 내용을 직접 확인 | `web.run`의 `find` |

이하 절차에서는 위 기능을 `내장 웹 검색 도구`와 `페이지 열기 도구`라고 부른다.

## 세 검색 경로의 역할이 다르다

| | 네이버 뉴스 탭 | 네이버 웹문서 탭 | 내장 웹 검색 |
|---|---|---|---|
| 강점 | 국내 보도 **전수 색인** — 업계지·중소 매체까지 | 뉴스 색인 밖 **국내 문서** — 정부 공고·대학·기관 페이지 | 공식 사이트·제품 도메인·영문 자료 |
| 약점 | 뉴스 색인 밖(공고·기업 뉴스룸)은 못 잡음 | 관련도순만, 날짜 필터 없음 | **US 인덱스** — 국내 매체를 통째로 놓침 |
| 용도 | 사실관계 뼈대, 관계자 인용, 업계 맥락 | 국내 1차 소스 — 공고·모집요강·정책 원문 | 영문·글로벌 1차 소스 발견 **전용** |

2026-09-01 실측: 같은 대상을 내장 웹 검색만으로 조사했을 때 국내 매체 4곳(데일리안·
머니투데이·뉴스1·매일경제)에 끝내 도달하지 못했고, 그 매체에만 있던 3축 평가 체계·
업계 통계가 통째로 빠졌다. 반대로 네이버만으로는 제품 공식 사이트의 플랫폼 구조를
놓쳤다 — 뉴스 색인에 없기 때문이다.

웹문서 탭도 같은 날 실측: 'kdt ai캠퍼스'를 뉴스 탭만 돌리면 10건 전부 기사였고,
**고용노동부 참여기관 확정 공고·대학별 모집공고는 웹문서 탭에만** 있었다. 거꾸로
'코파프로브'는 웹문서 탭이 뉴스 탭 색인 밖 매체 기사까지 물어왔다. **셋 다 돌려야 한다.**

자동화 브라우저의 구글 검색은 즉시 reCAPTCHA에 막힌다. 네이버는 정적 요청을 막지 않는다.

## 하드 룰

**검색엔진 요약과 페이지 열기 도구의 자동 요약을 사실 근거로 쓰지 마라.** 반드시
원문 텍스트를 확보해 직접 읽는다. 요약 모델은 부차적으로 보이는 인용·수치를
소리 없이 버린다.

> 실측(2026-09-01): 페이지 열기 도구로 읽은 아시아경제 기사 요약에서 심사 절차 전체가
> 빠졌다. 원문 본문에는 '블라인드 평가 리포트를 바탕으로 참가자들과 공개 토론을
> 진행했다'가 그대로 있다.

## 절차

### 0. 쿼리 축을 먼저 설계한다

**제품·대상 이름만 검색하면 절반을 놓친다.** 축을 다섯 갈래로 벌려 놓고 시작한다.

| 축 | 예 |
|---|---|
| 대상 표기 변형 | `Cofa-Probe` · `코파 프로브` · `코파프로브` |
| 주체 + 대상 | `크래프톤 코파 프로브` |
| **주체의 배경·전략** | `크래프톤 AI 퍼스트 전환` |
| **파트너십·확산** | `크래프톤 원티드랩` · `올리브영 AI 채용` |
| **업계 맥락·경쟁사** | `게임사 AI 채용 평가` · `코딩테스트 폐지` |

아래 두 축은 빼먹기 쉽고, 빼면 대상이 업계에서 차지하는 위치를 못 쓴다. 실측 사례에서
파트너십 건은 검색엔진 한계가 아니라 **쿼리를 안 던져서** 누락됐다.

### 1. 세 경로를 병렬로 돌린다

```bash
# 뉴스 탭 — 보도
uv run ${CLAUDE_PLUGIN_ROOT}/skills/websearch-enhanced/scripts/naver_search.py \
  --query "코파 프로브" --query "Cofa-Probe" --query "크래프톤 코파 프로브" \
  --pages 2

# 웹문서 탭 — 공고·기관·대학 페이지 (같은 키워드 축으로)
uv run ${CLAUDE_PLUGIN_ROOT}/skills/websearch-enhanced/scripts/naver_search.py \
  --query "코파 프로브" --query "크래프톤 코파 프로브" \
  --pages 2 --where web
```

웹문서 탭 결과는 press 자리에 사이트명이 오고 날짜 라벨이 없는 항목이 많다.
`--from`/`--to`는 뉴스 탭에만 적용된다.

첫 라운드는 **키워드 6개 이내 · `--pages 2`**로 시작한다. 축 다섯 갈래를 전부
키워드로 펼쳐 한 번에 던지는 게 아니라, 축당 1~2개를 고른다. 8개 × 3페이지처럼
연속 요청이 길어지면 네이버가 간헐적으로 403을 던진다(스크립트가 1회 재시도하지만
안 맞는 게 낫다). 스니펫을 보고 나면 어떤 축이 비었는지 보이므로, 두 번째 검색은
그때 그 축만 좁혀 던진다.

네이버 검색과 **내장 웹 검색 도구를 함께 실행한다.** 내장 웹 검색의 용도는 1차 소스
발견으로 한정한다 — 공식 사이트, 제품 도메인, 기업 뉴스룸, 채용 공고, 영문 발표.
내장 웹 검색이 물어온 국내 기사 목록은 편향된 표본이니 보도 커버리지는 네이버
결과로 판단한다.

키워드별 수집 건수가 stderr에 찍힌다. **0건인 키워드는 표기가 틀린 것**이니
스니펫에서 실제 매체가 쓰는 표기를 확인해 다시 돌린다.

### 2. 기간을 정한다

`--from`/`--to`를 생략하면 **전체 기간**을 검색한다. 처음에는 생략해서 대상이 언제
등장했는지 파악하고, 특정 사건 전후를 파고들 때만 좁힌다.

```bash
--from 20260701 --to 20260901   # YYYYMMDD, 뉴스 검색에만 적용됨
```

날짜 라벨은 `3일 전`처럼 상대 표기로 오기도 한다. 정확한 날짜가 필요하면 원문을 열어야 한다.

### 3. 스니펫을 훑어 읽을 기사를 고른다

기본 출력은 표 형식이다(`--format json`으로 후속 처리용 JSON도 가능).

같은 사건이면 **대부분의 기사가 같은 보도자료를 복붙한 것**이다. 20건이 모두
비슷하다면 정보가 20건 있는 게 아니라 1건 있는 것이다. 스니펫이 이미 사실관계
뼈대를 준다는 걸 믿어라 — 원문은 스니펫이 답하지 못하는 것(정확한 수치, 발언
전문, 맥락)을 채우는 용도다.

**fetch 예산: 첫 라운드 6건 이내, 조사 전체 10건 이내.** 실측(2026-09-01, 같은
과제 병렬 비교): 원문 36건을 뽑은 조사는 10여 건을 뽑은 조사보다 새로 확보한
사실이 없었고 토큰만 2배를 썼다. 한계 기사의 정보 가치는 5~6건째부터 0에
수렴한다. 예산 안에서 다음 세 종류를 **각각 최소 1건씩** 포함한다.

- **심층·해설 기사(필수)** — 보도자료에 없는 분류 체계·배경·인용이 여기에만 있다.
  제목이 설명형이거나 스니펫에 관계자 발언이 들어 있으면 신호다. 스트레이트만
  6건 읽으면 같은 문장을 여섯 번 읽는 것이다.
- **가장 자세한 스트레이트** — 세부 수치·고유명사를 가장 많이 담은 것
- **다른 각도** — 경쟁사·업계 맥락·비판적 논조

### 4. 원문 본문을 뽑는다

```bash
uv run ${CLAUDE_PLUGIN_ROOT}/skills/websearch-enhanced/scripts/fetch_article.py \
  --out-dir ./articles "https://..." "https://..." "https://..."
```

URL을 여러 개 주면 병렬로 받는다. 출력 머리의 `SELECTOR:` 줄이
`fallback:body`면 그 매체의 본문 컨테이너를 못 찾았다는 뜻이라 추천 기사·랭킹이
일부 섞일 수 있다 — 본문이 어디서 끝나는지 보고 읽어라. 자주 쓰는 매체가 계속
`fallback:body`로 나오면 `fetch_article.py`의 `BODY_SELECTORS`에 셀렉터를 추가하면 된다.

**1차 소스는 `--raw`로 받는다.** 공식 사이트·제품 랜딩·기업 뉴스룸은 언론사 CMS
셀렉터에 걸리지 않는다.

```bash
uv run ${CLAUDE_PLUGIN_ROOT}/skills/websearch-enhanced/scripts/fetch_article.py \
  --raw --out-dir ./sources "https://제품공식사이트/" "https://기업뉴스룸/..."
```

### 5. 커버리지를 확인한다 (노트·보고서로 남길 조사)

**추가 fetch를 하고 싶을 때 반드시 거치는 게이트이기도 하다.** "혹시 몰라서"
기사를 더 뽑는 대신, 지금 가진 문서로 coverage를 돌려 MISSING을 증명한 뒤
그 사실을 겨냥한 검색·fetch만 한다. 보강 라운드는 **1회로 끝낸다** — 두 번째
보강 후에도 MISSING인 사실은 더 파지 말고 노트에 '미확인'으로 표기한다.
확인 안 된 사실을 정직하게 남기는 것도 조사 결과다.

원문에서 뽑은 핵심 사실을 키워드로 만들어 **어느 문서에도 없는 항목이 있는지** 본다.

```bash
uv run ${CLAUDE_PLUGIN_ROOT}/skills/websearch-enhanced/scripts/coverage.py \
  --docs-dir ./articles --terms "메타 하네스,3축,원티드,관계자 인용,투자액"
```

- `MISSING`(전 문서 0회) — **아직 도달 못 한 사실이다. 0단계로 돌아가 축을 늘려라.**
- `SINGLE`(한 문서만) — 교차 확인 불가. 그 원문을 직접 읽고 채택할지 판단한다.
- `CROSS` — 교차 확인됨.

한 번 답하고 끝낼 질문이면 건너뛴다. 노트로 남길 조사에서만 건다.

**키워드는 반드시 `fetch_article.py`가 뽑은 본문에 건다.** 페이지 전체 HTML을 긁어
세면 사이드바 추천 기사 제목이 섞여 들어와 "이 기사에 있다"고 오판한다.

> 실측: 서울경제 페이지 전체(7478자)에는 특정 인명과 해외 컨설팅사 통계가 나타났지만,
> 기사 본문(1783자)에는 없었다 — 옆에 붙은 다른 기사 목록이었다. 이 오판 때문에
> '요약이 정보를 버렸다'로 잘못 진단할 뻔했다. 실제로는 그 기사에 처음부터 없었다.

### 6. 정리한다

스니펫만으로 쓰지 말고, 최소한 다음은 원문에서 확인한다.

- **숫자와 고유명사** — 상금, 인원, 투자액, 날짜, 조직명, 직책. 매체마다 틀리게 옮긴다.
- **표기 오류** — 실측 사례: 같은 솔루션을 한 매체는 '코파-프루브'로 오기했다.
  표기가 갈리면 가장 많은 매체가 쓰는 형태를 본문에 쓰고, 변형은 병기한다.
- **날짜** — 상대 라벨(`3일 전`)은 원문 발행일로 바꾼다.
- **당사자 발언** — 발표·논쟁·평가가 얽힌 주제라면 핵심 쟁점에 당사자의 실명·직책
  발언을 1~2건 싣는다. 심층 기사를 읽는 이유의 절반이 이것이다. 수치와 날짜만
  나열된 노트는 연표이지 조사가 아니다. (통계·법령처럼 발언 주체가 없는 주제는 예외.)

출처는 `매체, 「제목」 날짜 — URL` 형태로 남긴다. 나중에 검증할 사람이 바로 열 수 있어야 한다.
1차 소스(공식 사이트)는 보도와 구분해 적는다 — 신뢰도가 다르다.

## 옵션 요약

`naver_search.py`

| 옵션 | 뜻 |
|---|---|
| `--query` (필수, 반복) | 검색 키워드 |
| `--pages N` | 키워드당 SERP 페이지 (기본 2 = 20건) |
| `--from` / `--to` | 게시일 YYYYMMDD, 함께 지정. 생략 시 전체 기간 |
| `--where` | `news`(기본)·`web` — 검증됨 / `blog`·`view` — best-effort |
| `--format` | `table`(기본) / `json` |
| `--out FILE` | 파일로 저장, stdout에는 요약만 |

`fetch_article.py`

| 옵션 | 뜻 |
|---|---|
| `--raw` | 언론사 셀렉터를 건너뛰고 페이지 전체 추출 (공식 사이트용) |
| `--chars N` | 기사당 최대 글자 수 (기본 6000) |
| `--out-dir DIR` | 기사별 .txt로 저장 |

`coverage.py`

| 옵션 | 뜻 |
|---|---|
| `--docs` / `--docs-dir` | 대상 문서 (파일 나열 또는 디렉토리) |
| `--terms` / `--terms-file` | 확인할 사실 키워드 (쉼표 구분 / 한 줄에 하나) |
| `--strict` | 띄어쓰기·하이픈 차이를 구별 (기본은 무시하고 같은 것으로 봄) |
| `--json` | JSON 출력 |

## 막혔을 때

- **전 키워드 0건** — 네이버 마크업이 바뀌었을 수 있다. `agent-browser`가 설치돼
  있으면 자동으로 폴백한다(`pnpm add -g agent-browser`). 폴백도 0건이면
  `naver_search.py`의 `RE_TITLE` 등 정규식이 실제 HTML과 맞는지 확인해야 한다.
- **특정 키워드만 0건** — 표기 문제다. 스크립트가 아니라 키워드를 고쳐라.
- **기사 본문이 안 나옴** — 로그인·유료 장벽이 있는 매체다. 다른 매체의 같은 사건
  기사로 대체하는 편이 빠르다.
- **`coverage.py`가 다 MISSING** — 문서가 NFD로 저장돼 있어도 스크립트가 NFC로
  정규화하니 정상이면 그럴 수 없다. 키워드가 본문 표기와 다른지부터 보라.
